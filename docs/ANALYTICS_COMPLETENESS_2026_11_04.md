## Изменения

- Штатный сбор ждёт только точный pre-network
  `Deferred('worker_or_profile_busy')`, сохраняя исходный deadline и одну
  reservation страницы. Leases и SQLite-транзакции во время сна не удерживаются.
  Ошибки чтения/авторизации/защиты и исчерпание бюджета не повторяются.
- `LiveReader` принимает проверенные `wall_filter` и `use_cache`.
  Только прежний `owner` с `use_cache=True` использует общий owner-cache.
  Другие фильтры и принудительное сетевое чтение не читают и не заменяют его.
  Единый API-ledger, pacing и runtime/OS guards сохранены.
- Диагностический `probe-analytics-counts.py` больше не меняет transport
  при включённом owner-cache. Все варианты читаются раздельно с общим
  потолком 60 HTTP. Метаданные ограничены проверенными числами и enum;
  неизвестные coowners сохраняются только как shape/count. Невалидный count
  останавливает probe без повтора, строки исключений не экспортируются.
- Совместные публикации разрешаются только по строгому эмпирическому
  witness: точный отрицательный ID запрошенной стены и положительный local
  post ID в `coowner_post_id`, оба владельца в уникальном `coowners.list`,
  пустой `requests`, проверенные типы post/inner_type и известная структура.
  Остальные foreign objects по-прежнему дают partial. Разные local IDs
  не подменяют canonical identity; обычные собственные посты работают как раньше.
- Дата оригинала совместного поста может предшествовать его размещению
  на стене соавтора. Поэтому только даты собственных незакреплённых записей
  задают порядок и границу пагинации. Старый foreign original не обрывает
  чтение; дата foreign original новее предшествующей собственной записи
  по-прежнему считается противоречием и даёт partial.
- Добавлены таблицы `analytics_post_identities` и `analytics_identity_witnesses`
  в отдельной аналитической базе. Прежние таблицы/строки не мигрируются. Снимок хранит local key, новая
  связь хранит canonical owner/post и вид proof. Конфликт привязки останавливает
  запись. Ранее доказанная identity сохраняется при недоступности local alias,
  а счётчики остаются NULL. Метаданные дат вне периода сохраняются до фильтрации:
  их противоречие не теряется при restart. CSV дополнен canonical owner/post/URL.
- Правила новых замеров — v1.2. Сумма округа учитывает canonical post один раз,
  используя один последний целый снимок. Статистика каждой стены сохраняет
  её размещения. Разные даты одного canonical post дают partial, последний NULL
  не заменяется старым счётчиком. Старые frozen payload остаются неизменны.
- Читающий endpoint панели использует тот же canonical report внутри прежней
  read-only транзакции. Ссылки ведут к каноническому посту, при этом local IDs
  сохранены. Отдельного несовпадающего районного расчёта в панели больше нет.

VK официально описывает совместные публикации с едиными реакциями:
https://vk.com/press/co-authored-publications (31 марта 2025).
Открытая API-схема 5.199 не определяет `coowners`; наличие поля само по себе
не разрешает приписать чужой пост стене или дважды сложить его счётчики.
Фильтры `owner/all/others` определены в
https://github.com/VKCOM/vk-api-schema/blob/master/wall/objects.json.
