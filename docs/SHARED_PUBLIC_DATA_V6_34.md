# Единый сбор публичных данных v6.34

Пользователь23октября2026 разрешил единый сбор для аналитики, очереди и вебки,
сохранение исторических снимков, свежие счётчики перед действиями и установкуVM.

Общий VKReadClient использует отдельный public store `vk_public_data.sqlite3`.
Успешная страница wall.get сохраняется один раз с точным временем API-наблюдения;
аналитика, каталог, обновление перед пачкой и статистика запрашивают её через
один интерфейс. Ключ страницы: version/filter/group/count/offset. Повторное чтение
<=300сек переиспользует страницу, не расходуя API ledger. Это выбор реализации,
не новая пользовательская настройка. Cache metadata не содержит ключей/токенов.

Перед пачкой требуется observation>=начала текущего refresh; прежний cache не
разрешает действие. Budget/stop/unknown counts/guards не обходятся. Только
реальный HTTP расходует прежний общий ledger5000/24ч, pacing>=5сек. Общий OS lease
для загрузки страницы и повторная проверка cache устраняют параллельные запросы.
Существующие activity/profile/worker guards сохраняются. При сбое store нельзя
молча переходить к самостоятельной повторной загрузке.

Public store содержит append-only страницы и числовые наблюдения по постам.
В прежней operational DB сохраняются совместимые проекции для очереди/вебки;
аналитические run/snapshots/frozen reports остаются отдельными и неизменными.
Любой общий wall.get, включая analytics, обновляет только публичные совместимые
api_seen_posts/api_post_engagement проекции общей БД. Это не добавляет actor
attempts/действия и не меняет курсоры. Более старое наблюдение не заменяет новое.
Новые аналитические снимки сохраняют исходное observed_at страницы, а не время
чтения кеша. Никакой backfill не объявляет старый счётчик свежим. Исторические
посты/NULL/partial/недоступные ID сохраняются. При внедрении v6.34 список
действий оставался57. По отдельному прямому запросу25октября добавлены семь
конкретных источников: текущий явный список64 совпадает с frozen аналитическим
реестром. Будущие добавления в аналитику автоматически не разрешают действия.
Подробности и фактическая установка: SOURCE_GROUPS_64_2026_10_25.md.

Явный probe wall.getById остаётся отдельной проверкой возможностей; его ответ
нельзя положить под ключ wall.get. Неподдерживаемый1051 не обходится.

Активация через локальный `.vk-public-data.json` version1/enabledtrue. До
активации старые вызовы совместимы. Конфигурация принадлежит runtime root,
никакого автоматического включения на старой локальной копии. Исторические БД,
общий расход и расписание не заменяются при установке.

Штатный analytics08/20 теперь читает страницы100, как очередь и статистика.
Явный иной count/offset — отдельная страница: недостаточный по объёму ответ
не подменяет полный. Даже в пределах одной секунды старый кеш не проходит
fresh_after: граница начала refresh сохраняется с микросекундами.
Поздняя отмена по deadline/stop/window проверяется после pacing и до записи
api_read_attempts: неотправленный HTTP не расходует общий ledger. Расписание,
слотовый консервативный attempted_reads и запрет catch-up не меняются.
