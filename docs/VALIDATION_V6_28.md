## Историческая проверка фонового dry-run 2026-10-21

Сначала проверен ночной выход рабочего окна без действий. Затем по новому указанию «реальное тестирование, но без выполнения действий» live-worker остановлен, задача отключена, и установлена заново **только с `--scheduler-daemon --dry-run`**. Состояние на этом этапе: Windows-задача `VKUnifiedDailyWorker` работает, heartbeat свежий, `mode=dry_run`, `phase=waiting_window`, `paused=null`, jobs0. В рабочем окне этот режим обновляет API и очередь, но не вызывает исполнение действий и не резервирует пачки.

Установщик по умолчанию dry-run; при смене режима сначала отключает старые триггеры, просит worker завершиться и ждёт до 30 секунд, не оставляя старый live-процесс за новой dry-run-задачей. Повторная установка проверена: старый процесс завершён, новый запущен в dry-run. В Codex включён heartbeat-контроль каждые 30 минут, сообщения только при существенном изменении/ошибке; он также не имеет разрешения включать реальные действия.

Первый полный дневной цикл реальной отправки v6.28 не выполнялся. Реальная публикация community v6.27 остаётся отдельным историческим результатом. Компьютер должен быть включён, пользовательская Windows-сессия активна; после сна пропущенные пачки не догоняются.
