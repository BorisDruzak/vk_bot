## Исправление worker

- `vk_community_ui.repost_reference` читает только точный объект текущего исходного поста из известных JSON-prefetch `wall.get`/`wall.getById`. Серверный API `wall.getById` не вызывается. `copy_history` распознаётся рекурсивно до единственного оригинала (не более8 уровней); неоднозначные/циклические/противоречивые цепочки, пользовательские владельцы и отсутствующие данные останавливают выполнение до отправки. Случайные ссылки и текст не доказательство.
- Перед отправкой повторно проверяются исходная цепочка и её исходная дата. Кнопка репоста относится к выбранному посту, история попытки остаётся по выбранному посту; проверка целевой стены ищет точный оригинал и свежую дату целевого репоста.
- Добавлена аккаунтная `community_source_refs`. Worker не отправляет другую обёртку того же оригинала в то же назначение, если известен verified/already/uncertain. Проверка повторяется перед резервированием. История разных аккаунтов и назначений разделена. Старые статусы не переписываются; перед отправкой назначение с непроверенными старыми связями блокируется. Все старые community-связи перед возобновлением проверяются читающим backfill; ограниченный просмотр стены не объявляется полным поиском всех исторических дублей.
- Не меняются окно09–19 YEKT, 50/10/20 на аккаунт, community10+10, <=4/пачку, >=10мин между фактическими пачками, sleep20, случайный сохранённый план без catch-up. Подтверждённая попытка83 продолжает расходовать прежнюю единицу лимита; новых попыток при ремонте нет.

Ручной CLI v6.27 сохраняет прежний поток; новый разбор и канонический guard в этом исправлении подключены к ежедневному worker.
