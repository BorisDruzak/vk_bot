# Аналитика госпабликов — план и решения

Цель: отдельный читающий расчёт по приказу №111 от 14.09.2026, приложение1,
пункты3–3.3, с проверкой по предоставленной выгрузке только Сосновского МО.
Основание: подробное прямое задание пользователя «Реализуй … Пробуем, тестируем».

Архитектура: отдельные модули Python/stdlib и отдельная SQLite. Существующий
VKReadClient используется исключительно для общего ledger, pacing и guards.
Ни схемы, ни строки истории действий не изменяются. Runtime API только на VM,
с краткой exclusive activity/global lease на каждый запрос; занятость откладывает
сбор без остановки worker. Профили не открываются.

Выбор реализации: расширение текущего кеша потеряло бы историю; отдельная база
с append-only снимками сохраняет измерения и не связывает аналитику с actor.
Веб-панель не является обязательной частью этого задания; доступ через CLI,
JSON/CSV и читаемый HTML отчёт. Отчёты и реестр локальные, исключены из Git.

- [x] Тесты: пример2.7/75, cap, NULL/zero, суммы против средних, недели/репосты,
  исключения, snapshot/retry/resume, ошибки/пагинация/pinned, частичный импорт.
- [x] Store + расчёт: publications, snapshots, runs, frozen groups/reports,
  official measurements; уникальность run/group/post, новая run — новый snapshot.
- [x] Импорт XLSX/CSV/manual; отдельные per-community и district measurements.
  Только точный municipality, оригинал XLSX не меняется. Извлечение stdlib XML.
- [x] Сбор: wall.get до границы периода; checkpoint каждой страницы; при resume
  незаконченной группы повтор с головы с дедупликацией, изменение count — partial.
  wall.getById opt-in batch1..100;1051 сохраняется как unsupported, без обхода.
- [x] CLI collect/report/import/manual; сверка по тем же границам периода;
  P3.1/P3 только при достаточных входах; отдельный diagnostic mean ER.
- [x] Изолированные тесты, проверка VM ledger/history, реальный сбор64 групп,
  сверка и документация фактических результатов; independent final review.

Параметры, требующие ЦУР: timezoneYEKT, границы недель (period/calendar clip/
full/complete), включение репостов, страницы-визитки, точное время измерения,
опубликованные за период посты против приращения просмотров в периоде.
Отсутствующие views и недоступные посты — NULL, итог incomplete, не ноль.
Отрицательные/NaN/невалидные числа отклоняются. P3.3=min(100,ER/3.6*100).
Основной ER — отношение сумм, diagnostic mean не подменяет основной расчёт.
