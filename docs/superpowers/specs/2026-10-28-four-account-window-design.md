# Четыре аккаунта и расширенное окно

Пользователь выбрал расширить время работы, сохранив одинаковые квоты всех
аккаунтов. Вместо уменьшения квот либо сокращения пауз используем окно
09:00–22:00 YEKT и 50/10/20 на каждого: 320 попыток, 80 пачек по четыре.
Время 22:00 выбрано исполнителем: минимальный размах уникальных интервалов
для 80 пачек вместе с 600 сек резерва составляет 46341 сек (12:52:21).

Все интервалы >=540 сек, sleep после попытки >=20 сек, общий API ledger
5000/24ч, guards, изоляции и история сохраняются. Никакого catch-up.
Сохранённые day plans не переписываются; новое окно и квоты применяются
к первому ещё не запланированному дню. Новый аккаунт подключается отдельно,
включение очереди требует свежего proof и явного действия пользователя.

Проверка вместимости формы и повторного подключения использует ту же
настроенную будущую policy, что и scheduler. Панель показывает текущее
окно сохранённого дня и будущее окно; статические подсказки 09–19 убираются.

Подключение №6 уже запущено и ожидает activity lease. Проверка не останавливает
worker и не обходит lease. Установка кода выполняется только после завершения
входа и пачки со штатной остановкой для обновления.

Исходники и тесты выполняются в отдельной source-only копии. Живые реестры,
профили, секреты и SQLite не копируются в тестовое окружение. Исходная папка
не содержит .git; публикация GitHub в задачу не входит.
