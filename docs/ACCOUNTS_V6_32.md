# Добавление любого VK — v6.32, 23 октября 2026

После описанной ниже установки пользователь завершил оба входа: повторное
открытие профилей подтвердило оба ID, тесты выполнены изолированно, очередь
включена по прямому запросу. Актуальные факты — `STARTUP_V6_32.md`.

## Работа пользователя

Панель находится на основной Windows VM: `http://192.168.100.46:8787`.
Подключитесь к рабочему столу VM, нажмите «Добавить аккаунт» и при желании задайте
название. Откроется отдельный профиль Chrome на VM. Войдите в нужный VK: ID
определяется по точному собственному профилю в шапке, подключение и кеш
сохраняются автоматически. Номер прежней карточки и ручной ввод VK ID не нужны.
Окно созданного контекста закрывается после успешного подключения.

Для подключения уже известного VK система использует его прежнюю историю и
квоты; новый VK получает отдельную SQLite и нулевые квоты. Автоматика после
подключения выключена. Настройте квоты/назначения и включите её явно; перед
включением нужна свежая проверка входа. Старый сохранённый план дня неизменен,
новые настройки действуют с первого ещё не запланированного дня.

CLI сохраняет `--account-add NAME`, затем `--account N --login-only` на VM.
В режиме `add_any` вход запускается в интерактивном сеансе и завершается
автоматически. При подключении известного VK результирующий внутренний actor
может отличаться от временного номера нового профиля; используйте актуальный
список аккаунтов. Проверка точного actor ID перед действиями остаётся обязательной.

## Исправление причины

Прежний login worker удерживал исключительную `.vk-activity.guard` всё время
ручного входа. Второе окно получало RunAlreadyActive до запуска браузера.
`vk_activity.shared_activity` теперь держит совместную OS reader lease на том
же байте файла. На Windows используется LockFileEx, на POSIX — flock shared.
Разные профили входа совместимы; worker сохраняет исключительную lease пачки.
Занятость пачки отображается как `waiting_browser` с heartbeat, без остановки
worker. Отдельная исключительная lease каждого физического профиля сохраняется.
Файл guard не удаляется для освобождения занятого процесса.

`vk_connections` отделяет физический профиль от неизменного actor. Явная
миграция `--initialize` включает `account_flow=add_any` и архивирует прежние
карточки при отключённых аккаунтах. Bindings, история, расход, сохранённые
политики и браузерные папки не удаляются и не меняются местами. Свежий
наблюдённый ID выбирает существующего actor либо создаёт нового. Проверяются
захваченный путь профиля, занятость цели, in-flight job и вместимость будущего
расписания до публикации подключения. Pending/archived не допускаются в очередь.

## Проверка

- Локально: полный `python -m unittest discover -s tests` — 378 тестов, OK,
  60.489 секунды. В том числе 14 проверок подключения, 7 OS lease и 3 новых
  Node UI fixtures. Изменения прошли независимое ревью; два замечания о пути
  профиля и вместимости расписания исправлены и проверены регрессиями.
- На VM: тот же набор — 378 тестов, OK (skipped=7), exit code 0,
  93.133 секунды. Семь Node fixtures пропущены из-за отсутствия Node на VM;
  все они выполнены локально. Неудачная PowerShell-обёртка первого запуска
  не дала доказуемого итога; исправленный cmd redirect сохранил полный результат.
- Реальная панель VM: кнопкой добавлены два профиля, оба `awaiting_login`,
  `browser_opened=true`, `page_loaded=true`. Read-only EnumWindows из активного
  интерактивного сеанса 2 подтвердил два видимых окна Chrome с соответствующими
  названиями. В обоих окнах оставлен вход для пользователя.
- Браузерная проверка панели: нет заранее заданного ID и ручного finish,
  повторный старт заблокирован во время входа, ошибки консоли отсутствуют.
  При ширине 390px горизонтального переполнения нет; диалог сохраняет введённый
  черновик при фоновой работе, Escape закрывает его без сохранения.
- Перед установкой сделан приватный backup конфигурации и согласованных SQLite.
  Выполнена одна штатная остановка для обновления, затем обе задачи запущены.
  Обычные проверки worker не останавливали. Финальный heartbeat — live/
  waiting_batch, paused отсутствует, active_uncertain=0, две прежние изоляции.
- Реакционная история прежних двух actor совпадает с исходной: 72/61 записей,
  попытки 109/101. У двух новых профилей 0/0 попыток. Проверка не выполняла
  лайки, репосты или публикацию комментариев.

Фактическое завершение авторизации VK требует ввода пользователя в окнах VM;
до этого подключения не считаются авторизованными. Офлайн-тесты проверяют
автоматическое сопоставление существующего и нового VK ID без реальных входов.
