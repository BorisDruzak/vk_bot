## Задача на VM и приоритет worker

`vk_analytics_scheduled.py` допускает новые запуски только08:00–08:14:59
и20:00–20:14:59YEKT. В рабочее окно09–19 не начинает сбор. После25минут
или08:40/20:40 (что наступит раньше) новые HTTP-запросы не отправляет;
deadline проверяется также после общей API-паузы, перед транспортом.
Начатый запрос заканчивается в рамках существующего сетевого тайм-аута,
после чего освобождаются guard/lease. Занятость worker — немедленный deferred.
Общая защита API, бюджет5000/24ч и существующие ограничения доступа сохраняются.

Планировщик: `IgnoreNew`, фоновый priority8, RestartCount0,
StartWhenAvailable=false. Пропущенное время не догоняется. Системный
ExecutionTimeLimit30мин с AllowHardTerminate=false: нельзя принудительно
убивать читатель посреди существующего O_EXCL-guard и оставлять этот файл
воркеру. Основная остановка — Python deadline25мин с нормальным finally.
Задача worker и его настройки не изменены.

Реестровая копия берётся из analytics_local/observation-from-2026-10-14/registry.json,

## Ручной сбор (отдельно от штатного расписания)

Перед API-чтением проверить, что VM-реестр совпадает по SHA-256 с манифестом.
Местный helper подключается к VM по уже настроенному SSH-ключу, не выводит
сервисный ключ и не обращается к профилям браузера.

```powershell
# END — завтрашняя календарная дата YEKT, текущий день ещё открыт.
python -X utf8 tmp/omsu_vm.py run 2026-10-14 END
# При необходимости продолжить тот же run; page-size20 ограничивает
# смешанный хвост большой страницы. Не повторять без конца исторические NULL.
python -X utf8 tmp/omsu_vm.py resume RUN_ID 20
```

Один ограниченный resume допустим при `invalid_post` большой страницы.
При других ошибках сначала диагностировать причину; сохранять partial.
Если API-защита/лимит уже сработали, не делать новый запрос ради проверки.

Отчёт создавать НА VM через существующий CLI, с новым UTC-каталогом:

```powershell
.venv/Scripts/python.exe -X utf8 vk_analytics_cli.py --db vk_analytics.sqlite3 report --run RUN_ID --out analytics_local/observation-from-2026-10-14/UTC_STAMP --weeks period --freeze
```

Старый official-import за предполагаемые8–14 октября сюда не добавлять.
Период недель/reposts остаётся явно указанным вариантом, не подтверждённым ЦУР.
Отчёты скачивать отдельно; базу аналитики копировать только SQLite online backup.
