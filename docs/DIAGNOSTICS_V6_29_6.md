# Диагностика остановок — v6.29.6

По прямому запросу пользователя добавлены структурированные события scheduler. Обычная проверка не останавливает worker; необходимая установка этой версии выполняется отдельно, после завершения текущей попытки.

## Что сохраняется

- Строки `[VK EVENT]` в существующем `vk_scheduler.log` и отдельная таблица `scheduler_diagnostics` в scheduler SQLite. `--scheduler-status` показывает `last_diagnostic_error`.
- Начало/результат пачки, смена фазы и прогресс обновления счётчиков через каждые десять запросов.
- Для действия: номер job, порядковый аккаунт 1/2, вид действия, публичные ID источника/назначения, номер попытки после резервации, этап и прошедшее время. Этапы включают открытие браузера, навигацию, дату/цепочку источника, подготовку, проверку финального клика, подтверждение, обязательную паузу и закрытие браузера.
- При ошибке: фиксированный код, цепочка до четырёх типов исключений и до восьми кадров каждого типа — только известное имя файла и номер строки. Для VK API — числовой код, если он известен.
- Для проблем кнопок: раздельные причины отсутствующего корня/неоднозначной кнопки/неизвестного состояния/конфликта и разрешённые булевы/числовые признаки. Селекторы и защитные условия сохраняются.
- Для известных endpoint реакций VK: категория endpoint, HTTP-статус или фиксированный сетевой код, GET/POST. Наблюдатель только читает метаданные браузерных событий; запросы не отправляет.

HTTP 200 не доказывает успешную реакцию, HTTP-ошибка не всегда является `requestfailed`. Отсутствие сетевого события тоже не доказывает отсутствие отправки: VK может использовать другой endpoint. Логи помогают локализовать этап; результат по-прежнему требует прежних строгих доказательств. Старые причины остановок задним числом восстановить нельзя.

## Приватность и сохранение поведения

Новые события не содержат текст исключения, параметры/полный URL, заголовки, body запросов/ответов, cookies, токены, личный VK ID, DOM, текст поста, locals или абсолютные пути. Произвольные поля отбрасываются по allowlist. Это правило относится к новым событиям и не является обещанием очистки прежних локальных журналов.

Ошибка записи/регистрации/обработчика диагностики не создаёт остановку. Диагностика не коммитит уже открытую транзакцию вызывающего кода. Событие `final_click_check` записывается **до** последней проверки окна/deadline; после неё нет дополнительного синхронного логирования до возврата timeout. Этот порядок проверен отдельно искусственной задержкой логирования.

Резервации, квоты, прежний план, интервалы, `sleep(20)`, подтверждения и запрет повторного клика сохраняются. Ничего не превращается из uncertain в verified/пропуск. Изоляция job47 и failed задания18/61 сохраняются. Истории не очищаются. Дополнительных живых реакций для тестирования не выполняется.

## Проверка

Профильный набор проверяет редактирование ошибок, причины footer, отказ observer/хранилища, сохранение чужой транзакции, задержку перед последней проверкой deadline, единственную попытку и sleep20 при отказе telemetry, правильные browser_open/cleanup этапы. Локальные Chromium HTML/route фикстуры проверяют настоящий footer JS и HTTP 503/сетевой отказ без обращения к VK. Результат: 244 профильных офлайн-теста PASS; 49 изолированных Chromium-тестов PASS; compileall и git diff --check PASS. Повторное независимое ревью: 52 офлайн + 2 Chromium PASS, блокеров не найдено. Полный исторический набор не объявляется зелёным: известные прежние платформенные проблемы отдельных тестов не входят в эту приёмку.

Изменения локальные. Публикация в GitHub не выполняется этим обновлением.
