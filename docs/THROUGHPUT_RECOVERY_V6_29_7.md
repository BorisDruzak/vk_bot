## Изменения

- `vk_automation.json` и настройки scheduler используют5сек между API-чтениями; каталог принимает этот интервал. Новые ограничения ключа не обходятся, wall.getById не вызывается.
- Refresh прекращает поиск отсутствующих сегодняшних постов после доказанной границы дат упорядоченной незакреплённой страницы. Закреплённая старая запись, некорректный элемент или неупорядоченность не доказывают границу. Отсутствующее/неизвестное исключается, не становится нулём; свежие likes/reposts/comments и собственные verified учитываются прежним способом.
- `vk_scheduler_recovery.py` проверяет технический тип и отсутствие отправки: schedulerjob ещё без попытки, actor pending, нет новых actorattempts после baseline, иных intents/activeuncertain/защит. Разрешённые точные пользовательские изоляции учитываются; несовпадение любого поля блокирует.
- Доказанный технический сбой до отправки завершает job failed без возврата pending/повтора; `_batch_pool` очищается. Две последовательные ошибки получают backoff120/240сек; третья — `technical_error_repeated` и остановка. Продолжение только по следующему штатному интервалу, без catch-up. Типизированные сетевые ошибки читающего API и HTTP500/502/503/504 получают такой же bounded backoff. Реальное успешное чтение сбрасывает только read-streak, verified/already действие — только action-streak. Кеш/None не доказывают выздоровление.
- StopRun,guard/дата/профиль,429,auth,неопределённая/зарезервированная отправка, неполная/циклическая цепочка исключений и неподтверждённое закрытие context не восстанавливаются автоматически. Ошибка после intent сохраняет uncertain/расход и паузу.
- Ошибка закрытия уже закрываемой страницы не перечёркивает verified, только если cooldown завершён, context действительно закрыт и защит нет; сохраняется `cleanup_warning`. Ошибка context.close остаётся блокирующей.
- Диагностика: `technical_recovery`, `technical_error_deferred/backoff`, `technical_failures`, `technical_backoff_until`, `last_technical_recovery`. Старый last_diagnostic_error сохраняется как история, не заменяет проверку действующих paused/activeuncertain.
