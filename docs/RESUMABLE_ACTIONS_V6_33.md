# Возобновляемые действия v6.33

## Уточнение26октября: начальный chooser timeout

Установленный CommunityPreparationTimeout/community_prepare_timeout после
30сек ожидания первой опции сообщества доintent входит в эту же policy1.
После ожидания повторно проверяются account/source; guard ошибки остаются
немедленными. Exacttype/stage/community/job+pass nointent/noattempt обязательны.
Один повтор/две фазы; три подряд неуспешных logicalaction останавливают.
Policy0 и generic техническое восстановление не расширены. Старый общий
community_prepare и631 не мигрируют; историческая пауза сохранена.
Актуальный минимум между пачками540сек (выбор23октября), прочие квоты/guards
прежние. Подробности:CHOOSER_TIMEOUT_RETRY_2026_10_26.md.

Согласовано пользователем 23 октября 2026: один повтор на логическое действие;
после неудачного повтора продолжать очередь. Три подряд неуспешных логических
действия останавливают worker; verified/already сбрасывает счётчик.

Каждая настоящая попытка учитывается в квотах и четырёх местах пачки. Повтор,
не поместившийся в пачку, хранится до следующей штатной пачки того же дня;
пропущенные интервалы не догоняются. После перезапуска нельзя получить второй
повтор. История первой попытки и неопределённый исход сохраняются отдельно.

Повтор лайка разрешён только после свежей проверки точного аккаунта, источника,
даты, отрицательного JSON и footer и положительного can_like. Положительный исход
подтверждается без нового клика. Для репоста после durable intent повтор означает
только проверку результата: отсутствие в ограниченной стене не разрешает отправку.
Технический сбой до intent допускает второе выполнение с обычными guards.

Неразрешённый результат после повтора остаётся uncertain и исключается из выбора;
точная запись recovery разрешает продолжить другие действия. CAPTCHA, HTTP429,
защиты, неверный аккаунт, конфликт источника/даты/назначения и небезопасное
закрытие браузера останавливают сразу. Неизвестный сбой не считается безопасным.
Старые точные изоляции и прочие uncertain не меняются. Новое правило действует
после явного включения версии policy в scheduler_meta; миграция старой ошибки
требует отдельного проверенного аудита.

Окно09–19 YEKT, действия>=20сек, начала пачек>=10мин, квоты50/10/20 на аккаунт,
community10+10, API>=5сек и общий ledger5000/24ч сохраняются.

Pending-источник входит в следующий свежий API refresh, даже если неопределённость
исключила его из обычных кандидатов или закончилась квота. При нулевой квоте
допустима только проверка. Budget/unknown counts не разрешают старую очередь.
Известные обёртки одного signed original с held/verified историей исключаются
для того же назначения; финальный защитный precheck сохраняется.
