# Повтор подключения при подготовке пачки — 28 октября 2026

Прямой запрос пользователя после [разбора остановок](INCIDENT_2026_10_28.md):
при сетевом сбое несколько раз пытаться подключиться. Изменение относится к
публичному чтению свежих счётчиков перед действиями обычной пачки и её резерва.

## Поведение

- Для одной страницы wall.get — максимум три попытки: исходная и два повтора.
  При стандартной настройке ожидание перед повторами 5 и 10 секунд. Более
  длинная настроенная API-пауза сохраняется: например,20сек дают20/40сек.
- Повтор разрешён только точным VkApiReadDeadline/VkApiTransientRead с
  безопасной диагностикой сетевой фазы DNS/TCP/TLS/отправки/ожидания ответа.
  Тайм-аут загрузки helper/импортов, JSON и неизвестные ошибки не расширены.
  Проверяются cause и даже скрытый context; защита или неизвестная обёртка
  запрещает повтор. Реальный suppressed subprocess.TimeoutExpired разрешён
  только под уже доказанным сетевым read-исключением.
- Перед каждой попыткой действует обычный VKReadClient: общий rolling ledger
  5000/24ч, API>=5сек, прежний сетевой тайм-аут20сек, точные group/count/offset
  и fresh_after начала текущего обновления. Неудачные HTTP тоже расходуют бюджет.
  Свежий кеш допустим только по прежним точным правилам; старый кеш не разрешён.
- Ожидание разбито на шаги<=5сек с проверкой stop/paused/uncertain/platform/day/
  рабочего окна. Перед HTTP требуется запас20сек до прежнего cutoff подготовки
  (следующий сохранённый slot минус120сек). Паузы и окно не сокращаются.
- Если после сетевого сбоя повтор не помещается или кончился API-бюджет,
  исходная техническая ошибка идёт в существующий backoff/third-failure guard.
  Три исчерпанные попытки одной страницы считаются одним неудачным обновлением,
  а не тремя логическими сбоями worker. Частичная/старая очередь не разрешается.
  Прежний случай фактического пересечения deadline самим чтением сохранён.
- HTTP4xx,429, любой VKerrorcode, CAPTCHA/validation, auth, identity/source/
  destination/cleanup guards не повторяются этой новой политикой. Код7
  сохраняет прежнее локальное исключение недоступной группы.

## Панель и журнал

Свежий heartbeat `refreshing_counters` показывает «Повтор чтения 2/3» или3/3
и время ожидания, если оно ещё не прошло. Маркеры удаляются после успешного
чтения и сбрасываются для следующей страницы. Устаревший сигнал не показывает
ложный обратный отсчёт. Это отдельный показатель чтения, не повтор действия.

Событие `public_read_retry` сохраняет номер следующей попытки, максимум3,
числовую задержку, прежний фиксированный код ошибки и безопасные сетевые
поля. Ключи, URL, тело ответа, сырые исключения и DOM не записываются.

## Границы

Без изменения схем, зависимостей и политики повторов действий. Сохраняются
<=4реальные попытки/пачку,>=540сек между фактическими пачками,sleep>=20сек,
09–19YEKT, индивидуальные квоты50/10/20, прежние изоляции и история631.
Планы не переписываются, пропущенные пачки не догоняются, паузы не снимаются.
Плановая аналитика08/20 использует прежний транспорт; эта правка не добавляет
ей отдельные повторы и не меняет frozen snapshots или расчёт показателей.
