# Вкладка очереди ЭЦП в VK

Запрос: открыть очередь внутри VK-панели без перехода на другой адрес.
Выбран встроенный экран `/pos/` того же origin: общая сессия VK, узкий список
ресурсов, SAMEORIGIN только для встроенной страницы. Старый отдельный8788
сохраняется; cross-origin iframe потребовал бы второго входа и дополнительных
разрешённых origins. Перенос renderer в основной JS/CSS создал бы ненужную копию.

Из отдельного POS-проекта загружаются проверенный renderer и ReadOnlyQueue;
БД открывается mode=ro, без создания каталогов/таблиц и без вызовов исполнительных
команд. Snapshot/auth доступны только через VK session и CSRF. При выходе iframe
удаляется. Переключение вкладок сохраняет раскрытые строки. Окно/квоты/история и
оба worker остаются прежними. Обновление требует рестарта только VKWebPanel.

План (writing-plans, исполнение inline):
- [x] RED/GREEN: read-only БД, отсутствие создания файлов, auth/CSRF/read-only
  GET/static allowlist и узкие frame headers.
- [x] Вкладка и iframe с существующим renderer, относительные ресурсы/API,
  единая сессия и очистка при выходе. Никаких новых зависимостей.
- [x] Изолированный браузер: вход→ЭЦП→раскрыть попытку→другая вкладка→возврат→
  выход; desktop/mobile, консоль, пустой/недоступный backend. Browser plugin
  отсутствует в каталоге навыков; используется существующий Playwright MCP.
- [x] Backup и проверка SHA до установки, restart только VK-панели; чтение
  живого snapshot15/15 и сохранности POS/VK worker. Обновить контекст.
