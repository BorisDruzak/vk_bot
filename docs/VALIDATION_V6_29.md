# Проверка v6.29 — свежие счётчики перед пачкой

Дата: 2026-10-22. Версия локальная; в GitHub это изменение не опубликовано.

## Что изменено

Новый `vk_batch_engagement.py` обновляет перед пачкой подходящий возрастной слой через поддерживаемый ключом `wall.get`. Приоритет: сегодня прежде резерва семи дней, затем меньшая известная сумма likes + reposts + comments. В действие допускаются только реально прочитанные этим обновлением публикации с тремя корректными счётчиками. Комментарии только считаются.

Собственные verified обоих аккаунтов учитываются перед каждым выбором; старые результаты не прибавляются повторно поверх API. Отдельные назначения community считаются разными репостами; незавершённые/uncertain не выдаются за verified. Учёт квот, остановки и запрет повторных отправок сохранены. Выбор сохраняет числовое обоснование в `scheduler_priority_evidence`.

Миграции только добавляют nullable `comment_count` и таблицу обоснований. Профили, ключи, история действий и предупреждения не переносятся и не сбрасываются. API code 7 имеет отдельный часовой cooldown и не портит курсор фонового каталога. Ошибка ключа/429 останавливает работу.

## Проверки без действий

- 206 профильных офлайн-тестов PASS на временных базах: свежая сортировка, комментарии/NULL, два аккаунта и назначения, собственные действия без двойного учёта, обновление до выбора, нехватка API-бюджета, stop/429/конец окна, продолжения страниц, сохранение курсоров, резерв после обработки сегодняшних постов, фактический интервал пачек и его сохранение при перезапуске.
- 31 Chromium-проверка на локальных тестовых страницах PASS, включая ожидание подтверждения и единственную резервацию после ошибки финальной отправки. Действующий VK в этих тестах не используется.
- Живое читающее обновление 10:02:05–10:04:11 YEKT: 7 групп, 9 сегодняшних публикаций, 7 API-запросов, 126 секунд. Все три счётчика известны, пропущенных выбранных источников нет. Выбран источник с суммой 0+0+0. Истории попыток 78/69 до и после, все таблицы действий без изменений. Адаптер действий в проверке принудительно запрещён; scheduler использует временную копию состояния. Локальное доказательство: `C:\Temp\vk-v629-readonly-k9uq6akf\result.json`, в Git не включается.
- Текущий ключ отказал `wall.getById` кодом 1051. Обход/повтор не выполнялись; производственная реализация использует доступный `wall.get`, где `comments.count` подтверждён.

Полный исторический набор тестов Windows не объявляется зелёным: прежние ограничения описаны в VALIDATION_V6_26.md. Эта проверка не является новым тестом живых лайков/репостов и не доказывает завершение полного дневного плана.

## Неизменные ограничения

09–19 YEKT; по 50 лайков, 10 личных и 20 community на аккаунт, community по 10 на назначение; до 4 действий, по одному за раз; sleep20 после попытки; сохранённое случайное расписание без catch-up. Минимум 10 минут проверяется по первым фактическим резервациям разных пачек, в том числе после долгого чтения и перезапуска.

Минимум относится к свежим доступным кандидатам известного каталога, не ко всем публикациям VK в один момент. Чтение занимает время, ограничено 10 страницами на группу и общим API-бюджетом 2000/24 ч. Недоступные/непрочитанные посты исключаются, неизвестные счётчики не считаются нулём. Долгое обновление может уменьшить число фактических пачек: окно и лимиты ради заполнения плана не расширяются.
