# Время и очередь VK Unified
для изменения планировщика

Редактируемая техническая спецификация   •   29 октября 2026

Цель — зафиксировать действующие часы, ограничения и последовательность очереди, чтобы выбирать и реализовывать изменения по точным параметрам. Раздел 5 содержит поля для желаемых значений, приложение — все 80 сохранённых слотов на 29 октября.

Основной вывод: окно 09:00–22:00 уже действует. Неполная пачка может завершиться раньше из-за границы следующего слота и ожидания 540 секунд между фактическими началами действий. Увеличение числа пачек само по себе не увеличивает время внутри каждой пачки.

## 2 Сроки одной пачки

Обозначения: S — сохранённое начало текущего слота; N — начало следующего; E — конец рабочего дня; B = min(N, E). Для последнего слота B = E. Все сравнения используют актуальное время после медленных операций, а не старую отметку до чтения базы или подготовки браузера.

| Этап или ограничение | Точное правило | Где задано |
| --- | --- | --- |
| Получение слота | S ≤ now ≤ S + 120 с; опоздавший слот не догоняется | claim_batch и MAX_JITTER_SECONDS |
| Два старта пачек | Не менее 540 с между фактическими started_at; минимум 20 с после finished_at предыдущей | State.claim_batch |
| Обновление счётчиков | Срок подготовки Dread = B − 120 с. Перед HTTP требуется запас 20 с с учётом ожидания API | reserve_refresh_deadline; refresh.permitted / preflight |
| Пауза чтения API | Не менее 5 с между запросами общего читателя; тайм-аут транспорта 20 с | VKReadClient; bounded_transport |
| Готовность действий | Tready = last_action_batch.at + 540 с. Ожидание продолжается только в уже вовремя захваченной пачке | wait_batch_spacing; batch_spacing_ready |
| Новая попытка | Dintent = B − 60 с. При now ≥ Dintent новый intent / новая работа не разрешаются | action_time_closed; before_attempt |
| Конец рабочего дня | До резервирования требуется now < E − 30 с. Проверка перед финальным кликом выполняется отдельно | State.guard / action_now |
| Финальный клик | Timeout не более 9 с, остатка до E минус 5 с и остатка до B минус 20 с. При остатке ≤ 0 клик запрещён | State.click_timeout |
| После резервирования | Обязательный sleep не менее 20 с после попытки, включая ошибку и последнюю операцию | execute_action.cooldown |
| Завершение пачки | Подтверждение и cleanup уже начатого действия могут закончиться после Dintent. Это не разрешает запуск четвёртого действия | _run_batch; execute_action |

Готовность к действию наступает не раньше окончания обновления счётчиков и Tready. Приближённый остаток для запуска новых действий: Dintent − max(Trefresh_finished, Tready). Подготовка выбранной записи, браузер и финальные проверки также расходуют этот остаток.

Числа 120, 60, 30, 20, 9 и 5 секунд относятся к разным проверкам. Изменение одного числа не переносит автоматически остальные сроки. Срок HTTP также нельзя увеличивать без согласования с запасом перед Dread.

## 4 Порядок очереди и учёт времени

| Порядок | Действие планировщика |
| --- | --- |
| 1 | Читает сохранённый план текущего дня и проверяет рабочее окно, pause, stop, uncertain и доступность общего браузера. |
| 2 | Получает исключительную activity lease на всю пачку и захватывает текущий слот. Параллельных действий аккаунтов нет. |
| 3 | Обновляет свежие счётчики подходящих кандидатов через общий VKReadClient. Сегодняшние публикации имеют приоритет; резерв — предыдущие 7 дней. |
| 4 | При необходимости ожидает 540 с от last_action_batch.at предыдущей пачки. Повторно проверяет день, окно, защитные состояния и сроки. |
| 5 | В первую очередь рассматривает разрешённый pending-повтор, затем выбирает очередное новое действие по приоритету источника и расходу квот. |
| 6 | Открывает профиль выбранного actor; сверяет свой VK ID, источник, дату, доступность и точное назначение. Готовит кнопку до записи intent. |
| 7 | Перед попыткой и кликом повторяет guards; сохраняет durable intent / attempt, выполняет допустимое действие, выдерживает sleep 20 с и проверяет результат. |
| 8 | Выбирает следующий элемент после verified / already или допустимого пропуска. Максимум 4 реальные попытки, затем finish_batch и освобождение lease. |

Выбор не является фиксированной очередью «сначала все лайки, затем репосты». В текущем коде ключ выбора: возрастной слой → известность счётчиков → сумма likes + reposts + comments → доля использованной квоты категории → предпочтение другого actor → более новая публикация → actor, вид действия и назначение. Очередь пересчитывается между действиями. Историческое правило проекта описывает сумму likes + reposts без comments; это расхождение нужно явно разрешить при доработке приоритета.

### Общие ограничения

- Официальное чтение wall.get через единый ledger: не более 5000 HTTP-попыток за скользящие 24 часа, pacing не менее 5 секунд. Неизвестные счётчики не считаются нулём.
- Кеш обычно 300 секунд сохраняет исходное observed_at. Перед пачкой fresh_after не раньше начала её обновления; старые данные не заменяют неполное или неудачное обновление.
- Сетевое чтение одной страницы имеет максимум три подключения с ожиданием 5 и 10 секунд при базовой паузе API. Повтор разрешается только для доказанной сетевой ошибки и при запасе до прежнего срока.
- Один разрешённый повтор логического действия расходует те же квоты и места пачки. После durable intent репост повторно не отправляется; повтором служит проверка подтверждения. Три логических неуспеха подряд требуют attention.
- CAPTCHA, HTTP 429, неверный аккаунт, конфликт источника или назначения, небезопасный cleanup и неразрешённый uncertain сохраняют остановку. Проверка состояния сама по себе worker не останавливает.

### Направления доработки

Первое направление — сократить измеренные затраты подготовки внутри действия, сохранив identity, source, destination и финальные guards. Это увеличивает полезное время без изменения частоты попыток.

Второе — проектировать границы пачек с учётом ожидаемой готовности действий и времени выполнения четырёх операций. Если разрешать пачке выход за следующий сохранённый слот, нужно отдельно определить судьбу этого слота, единственность исполнителя, no-catchup и сохранение истории. Такая переработка не сводится к удалению проверки B − 60.

### Критерии приёмки

- Сначала воспроизвести пример 09:29 офлайн на временных базах и искусственных часах. Зафиксировать текущее поведение и ожидаемую разницу после изменения.
- Проверить поздний claim, ожидание 540 с, смену дня, следующий слот, последний слот, HTTP20, повтор5/10, расход квот и четыре места пачки.
- Проверить, что после intent не появляется повторная отправка; failed без attempt не превращается в verified; CAPTCHA/429/identity и uncertain по-прежнему блокируют действия.
- Сохранённый план не переписывать; новые параметры проверять для первого не спланированного дня. Тесты VM выполнять только в отдельной source-only копии без реестра, профилей, SQLite и секретов.
- Перед установкой сравнить SHA исходников и сделать backup. Штатная остановка допускается для установки после естественного завершения пачки; обычная диагностика не создаёт stop_requested.
- После установки проверить схемы, историю, квоты, задачи и будущий resume gate; отдельно принять штатную пачку по attempts и verified. Полный прогон тестов не доказывает выполнение дневной квоты.
