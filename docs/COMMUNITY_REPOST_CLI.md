# Репост в выбранное сообщество — v6.27

`--repost-community ID` задаёт одно целевое сообщество на запуск для `--account 1` или `--account 2`. ID вводится положительным числом, без минуса и без префикса `club`. Сообщество должно присутствовать в списке назначений выбранного аккаунта. Флаг `--only` по-прежнему фильтрует **исходные** группы.

Без `--repost-community` используется прежний режим репоста на личную стену. Его история, команды и CSV сохранены.

## Проверка без отправки

PowerShell, из рабочей папки проекта:

```powershell
python vk_unified.py --account 1 --run-actions --reposts 1 --repost-community 242481697 --max-posts 1 --dry-run
python vk_unified.py --account 2 --run-actions --reposts 1 --repost-community 242479058 --max-posts 1 --dry-run
```

`--dry-run` открывает исходный пост, проверяет аккаунт и точную дату, выбирает сообщество по ID и подтверждает значение в диалоге. Финальная кнопка не нажимается, лайки также не ставятся, даже если передан `--likes`. Попытки, запуски и результаты репостов не записываются. Возможна подготовка локальной схемы и обновление публичных метаданных в SQLite. `--confirm` несовместим с `--dry-run`.

`--max-posts` ограничивает число рассматриваемых исходных публикаций. Проверка выполняется только для доступных API-кандидатов; пустая очередь не доказывает доступность диалога.

## Команда выполнения

Форма явно разрешённого запуска с комбинированными бюджетами:

```powershell
python vk_unified.py --account 2 --run-actions --likes 5 --reposts 2 --repost-community 242479058 --max-posts 10 --confirm
```

В этой команде лайки относятся к исходным постам, репосты — к указанному сообществу. Числа ограничивают попытки за запуск; уже существующие реакции не увеличивают число новых подтверждённых действий. Если кандидатов недостаточно или действие не подтвердилось, результат не считается `complete`. При неопределённом исходе отправки сохраняется `uncertain`, выполнение останавливается, автоматического повтора нет. Комбинированный объём 5 лайков / 2 репоста в сообщество отдельно не проверялся. Реальная приёмка v6.27 выполнена четырьмя командами без лайков: по одному репосту в каждое из двух сообществ каждого аккаунта; все четыре подтверждены.

Прежний режим личной стены:

```powershell
python vk_unified.py --account 2 --run-actions --likes 5 --reposts 2 --max-posts 10 --confirm
```

## Обязательная пауза

После каждой зарегистрированной попытки отправки в сообщество скрипт вызывает `time.sleep(20)` до проверки целевой стены и следующего репоста. Пауза выполняется также при ошибке после резервации; она не отключается параметрами CLI. После последнего репоста пауза тоже сохраняется, поэтому последовательные команды для разных сообществ и аккаунтов разделены минимум 20 секундами. Это отдельная пауза отправки, дополнительно к пейсингу навигации.

## Локальная очередь и отчёт

```powershell
python vk_unified.py --account 1 --preview --repost-community 242481697 --max-posts 10
python vk_unified.py --account 2 --action-status --repost-community 242479058
```

Эти команды не запускают браузер. Они требуют локальную привязку аккаунта и корректную базу; каталог профиля Chromium для просмотра не требуется. Для выполнения, включая `--dry-run`, профиль обязателен.

Отчёт по умолчанию: `vk_actions_results_account_<номер>_community_<ID>.csv`. Переопределение — `--report-file PATH`. Поля: `community_id`, `source_post_url`, `repost_status`, `target_post_url`, `updated_at`. Отчёт личной стены не перезаписывается.

## Изоляция и подтверждение

- Используется отдельная SQLite каждого аккаунта. Дополнительная привязка `community_account_identity` запрещает принять историю другого VK ID.
- Ключ истории репоста: `(community_id, group_id, post_id)` внутри базы аккаунта. Личный репост и репост в другое сообщество не исключают пост из этой очереди.
- Исходные ID/точные даты каждый раз проверяются по текущему публичному API-каталогу базы №1, включая отзыв валидности. История реакций первого аккаунта не переносится во второй.
- Попытка сохраняется непосредственно перед финальным кликом; статус заранее становится `uncertain`. Новое `verified` требует точного поста на целевой стене, содержащего исходный репост и свежую точную дату. Счётчик репостов источника успехом не считается.
- Проверка целевой стены ограничена уже отрисованными постами. Она не является полным поиском старых репостов. Отсутствие совпадения не доказывает отсутствие исторического дубля. Отсутствие свежего подтверждения после отправки оставляет `uncertain`.
- HTTP 429, CAPTCHA, несовпадение аккаунта, изменившийся диалог или неоднозначное назначение останавливают работу. Снятие предупреждений и повтор сомнительных отправок не автоматизированы.

Проверки и границы приёмки — в [VALIDATION_V6_27.md](VALIDATION_V6_27.md). Исторический реальный тест 30/30 v6.26 относится к личной стене.
