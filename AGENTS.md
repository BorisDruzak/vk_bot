  небезопасный cleanup — немедленная остановка без повторов и обхода.

## Вход и статистика — v6.31

- Сохранённая VK ID binding не доказывает вход. Свежий proof обязан сверять точную
  ссылку собственного профиля в шапке с ожидаемым ID, профилем, машиной и временем.
  Legacy ready, stale и wrong_account не разрешают finish/enable; отрицательная
  проверка отменяет прежний matched. Не переставлять привязки/истории автоматически.
- В группах обязательны реальные API лайки/комментарии/репосты/просмотры по <=100
  записям на группу, known_sum, K/N и время. NULL не ноль. Формулы вовлечённости
  пользователь задаст позже. Читающий refresh сохраняет общий ledger5000/24ч,
  API>=5сек, guards; не пишет действия/курсоры. Mixed page сохраняет только прежне
  валидные записи и явно partial. См. docs/AUTH_STATS_V6_31.md.
- `.vk-activity.guard` — OS lease целой пачки и login/statistics readers; не удалять
  файл ради освобождения процесса. Обычная занятость до claim не технический сбой.

## Проверка не является основанием для остановки

- Прямое уточнение пользователя: остановка должна происходить по требованию исполняемого скрипта, а не ради выполнения проверки. Обычный мониторинг, аудит, тестирование и проверка статуса выполняются без остановки работающего worker.
- Команда «проверь» сама по себе не разрешает ставить stop_requested, вызывать --scheduler-stop, останавливать Windows-задачу или завершать процессы. Если для дополнительной диагностики занят профиль/lock, отложить её до доступного момента; не освобождать lock остановкой процесса.
- Сохранять защитные требования самого скрипта: StopRun/paused, новый неразрешённый uncertain, CAPTCHA/429, несовпадение профиля, окна и лимиты. Проверка не создаёт отдельную причину остановки и не отменяет уже сработавшую защиту. Применять действующие явно разрешённые исключения, включая изоляцию job47.
- Явная команда пользователя на остановку сохраняет приоритет. Штатная остановка, действительно необходимая для установки изменения, относится к отдельной операции обновления в рамках разрешения пользователя; её нельзя обосновывать одной необходимостью проверки. Для обычной проверки остановку не выполнять.
