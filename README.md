# VK Unified — локальный мониторинг и обработка публикаций VK (v6.26)

**Состояние на 21 октября 2026 года:** оба аккаунта прошли отдельные реальные тесты на 30 новых лайков и 30 новых репостов. Многопостовый режим второго аккаунта v6.26 завершился со статусом `complete`: все 60 действий подтверждены VK, проверено 35 публикаций за 31 минуту 44 секунды. Все выводы о платформенных ограничениях относятся к наблюдениям тестирования, а не к официальной «безопасной квоте» VK.

**GitHub проекта:** [BorisDruzak/vk_bot](https://github.com/BorisDruzak/vk_bot), основная ветка `main`. Правила для последующей работы — в [AGENTS.md](AGENTS.md).

**Версия кода и публикация результатов:** этот документ описывает локально проверенную v6.26. При подготовке публикации документации исходники `main` на `27a37bf38f909fe5fa4ec8f2be5175a530a0453b` оставались v6.25: многопостовый режим №2 в той версии ещё отсутствует. Обновление этих документов публикует результаты теста и контекст; для выполнения приведённых команд №2 нужна реализация v6.26. Перенос её кода и тестов в GitHub остаётся отдельной задачей.

Проект Python/Playwright + официальный VK API + SQLite. Рабочий сценарий: получать ID и точные даты публичных записей через `wall.get`, выбирать свежие записи за заданный период, хранить локальные результаты и отчёты; открывать конкретный пост в авторизованном Chromium только когда нужно проверить состояние или выполнить явно запрошенное действие. Скрипт не обходит CAPTCHA, требования входа или ограничения VK.

**Важно:** у аккаунтов независимые данные реакций и попыток: `vk_batch.sqlite3` принадлежит профилю №1, `vk_batch_account_2.sqlite3` принадлежит профилю №2 и дополнительно закреплена за VK ID. Публичный API-каталог хранится в базе №1; в базу №2 копируются исключительно проверенные публичные ID и даты, **не** лайки, репосты или ограничения первого профиля. До запуска действий необходимо проверить аккаунт №2 вручную.

## Быстрый запуск на Windows

Рекомендуется Python 3.11+ и обычный CMD:

```cmd
py -m pip install -r requirements.txt
py -m playwright install chromium
py vk_unified.py --account 1 --check-account
py vk_unified.py --account 2 --login-only
py vk_unified.py --account 2 --check-account
py vk_unified.py --accounts-report
```

Для чтения публичных стен нужен **сервисный ключ официального VK API**, который передаётся **только через переменную окружения** (не хранится в репозитории):

```cmd
set "VK_API_TOKEN=ВАШ_ЛОКАЛЬНЫЙ_КЛЮЧ"
py vk_unified.py --discover --only 188206921
py vk_unified.py --api-report
py vk_unified.py --preview --max-posts 20
```

Локальные диагностические команды:

```cmd
py vk_unified.py --status
py vk_unified.py --action-status
py vk_batch.py --safety-report
py vk_unified.py --accounts-report
```

### Отдельный запуск второго аккаунта (v6.26)

Сначала обнови общий каталог через VK API (команда выполняется **под аккаунтом №1**, сервисный ключ VK только локально):

```cmd
py vk_unified.py --account 1 --discover
```

Затем просматривай локальную очередь второго профиля и его отдельную базу:

```cmd
py vk_unified.py --account 2 --check-account
py vk_unified.py --account 2 --preview --max-posts 15
py vk_unified.py --account 2 --test-status
```

Ограниченный ручной тест на двух публикациях с раздельным бюджетом действий:

```cmd
py vk_unified.py --account 2 --run-actions --likes 2 --reposts 2 --max-posts 2 --confirm
py vk_unified.py --account 2 --action-status
```

Для запуска с отдельными максимумами 5 лайков и 2 репоста, с проверкой до 10 постов:

```powershell
python vk_unified.py --account 2 --run-actions --likes 5 --reposts 2 --max-posts 10 --confirm
```

Эта команда проверена через CLI в офлайн-регрессионном тесте: 5/2 попытки и подтверждённые тестовые результаты записываются только в SQLite №2; прежние реакции №2 повторно не выполняются, база №1 не меняется. Это не проверка реальных лайков и репостов в VK.

После проверки результатов в VK и отсутствия ограничений можно задавать другой конечный объём **самостоятельным запуском**, например `--likes 30 --reposts 30 --max-posts 60 --confirm`. Это максимумы **попыток за один запуск**, а не гарантия новых 30/30. Нет автоповтора, фонового задания или одновременной работы двух аккаунтов.

**Реальный тест №2 успешно пройден 2026-10-21:**

```powershell
python vk_unified.py --account 2 --run-actions --likes 30 --reposts 30 --max-posts 60 --confirm
```

Запуск №1: `complete`, 30/30 попыток лайка и 30/30 попыток репоста; VK подтвердил 30 новых лайков и 30 новых репостов на 35 проверенных публикациях. Время: 19:36:09–20:07:53 Asia/Yekaterinburg (14:36:09–15:07:53 UTC), длительность 31:44. `--account 2 --action-status`, журнал SQLite и CSV на 35 строк подтвердили итог; в CSV отмечено ровно 30 новых действий каждого типа. Ранее существовавшие реакции пропускались. История попыток аккаунта №1 осталась прежней (71 запись до и после теста); предупреждений VK на момент завершения не было. Это результат конкретного запуска, не гарантия последующих 30/30.

Отчёт №2: `vk_actions_results_account_2.csv`. Отчёт №1: `vk_actions_results.csv`. Нельзя менять cookie-файлы, переносить SQLite между аккаунтами, снимать CAPTCHA/HTTP 429 или пытаться обойти платформенные ограничения. Оба профиля запускаются последовательно; при сомнительном исходе дальнейшие клики запрещены.

## Защита данных

В публичный GitHub **не загружать**:

- `.vk-local-profile*`, cookies, localStorage, файлы браузерных сессий;
- `vk_batch.sqlite3`, `*.sqlite3*`, `vk_account_bindings.json` (локальные идентификаторы), `.vk-*.lock`;
- `VK_API_TOKEN`, `.env`, любые защищённые и сервисные ключи;
- реальные CSV-отчёты, авторизованный HTML/DOM VK, скриншоты с приватными данными;
- дампы HTTP, полный текст авторизованных страниц, логи с токенами.

См. `docs/ARCHITECTURE.md`, а также `docs/DEVELOPMENT_CONTEXT.md` для истории изменений и технических ограничений.
