# VK Unified — локальный мониторинг и обработка публикаций VK (v6.25)

**Состояние на 21 октября 2026 года:** однопрофильный механизм чтения публичных публикаций и подтверждения действий проверен на реальном VK; независимый второй Chromium-профиль прошёл проверку входа. Все выводы о платформенных ограничениях относятся к наблюдениям тестирования, а не к официальной «безопасной квоте» VK.

Проект Python/Playwright + официальный VK API + SQLite. Рабочий сценарий: получать ID и точные даты публичных записей через `wall.get`, выбирать свежие записи за заданный период, хранить локальные результаты и отчёты; открывать конкретный пост в авторизованном Chromium только когда нужно проверить состояние или выполнить явно запрошенное действие. Скрипт не обходит CAPTCHA, требования входа или ограничения VK.

> **Важно:** полная API-очередь и командные задания по-прежнему относятся **только к аккаунту №1**. Для №2 добавлен ограниченный разовый тест **одной явно указанной публикации** с отдельной базой `vk_batch_account_2.sqlite3`. Общие аккаунтные статусы никогда не копируются. Синхронной или массовой обработки с нескольких профилей нет.

## Быстрый запуск на Windows

Рекомендуется Python 3.11+ и обычный CMD:

```cmd
py -m pip install -r requirements.txt
py -m playwright install chromium
py vk_unified.py --account 1 --check-account
py vk_unified.py --account 2 --login-only
py vk_unified.py --account 2 --check-account
py vk_unified.py --accounts-report
```

Для чтения публичных стен нужен **сервисный ключ официального VK API**, который передаётся **только через переменную окружения** (не хранится в репозитории):

```cmd
set "VK_API_TOKEN=ВАШ_ЛОКАЛЬНЫЙ_КЛЮЧ"
py vk_unified.py --discover --only 188206921
py vk_unified.py --api-report
py vk_unified.py --preview --max-posts 20
```

### Разовый тест действий аккаунта №2 (v6.25)

После уже выполненной привязки двух VK ID выберите **одну** недавнюю публикацию из `--preview`/`--preview-pairs`; её ID должен присутствовать в общем API-каталоге (`wall.get`) за 7 дней. Сначала без кликов:

```cmd
py vk_unified.py --account 2 --check-account
py vk_unified.py --account 2 --test-post 188206921_13418
```

Пример ID в командах — **только пример**; замените на конкретную публикацию, которую хотите проверить. После визуальной проверки отдельно разрешите одно действие:

```cmd
py vk_unified.py --account 2 --test-post 188206921_13418 --test-actions like --confirm
py vk_unified.py --account 2 --test-post 188206921_13418 --test-actions repost --confirm
py vk_unified.py --account 2 --test-status
```

Можно выбрать `--test-actions both`, но для первой проверки рекомендуется запускать лайк и репост раздельно. `--confirm` разрешает действие **только на указанной публикации**, без обхода других групп/постов. Уже подтверждённое действие не повторяется; `uncertain` не сбрасывается автоматически. При CAPTCHA, VK HTTP 429 или несоответствии VK ID выполнение останавливается. Профиль и SQLite №1 не изменяются. Токен API для этих команд не нужен: только уже полученный локальный API-кеш.

**Это проверка одного профиля и одного поста, не многопрофильная кампания.** `--account 2 --run-actions` по-прежнему запрещён. Тестовый режим не гарантирует отсутствие платформенных ограничений.

Локальные диагностические команды:

```cmd
py vk_unified.py --status
py vk_unified.py --action-status
py vk_batch.py --safety-report
py vk_unified.py --accounts-report
```

Опции выполнения действий существуют для аккаунта №1 и требуют отдельного явного `--confirm`. Они не предназначены для обхода ограничений VK или для синхронного искусственного увеличения вовлечённости несколькими аккаунтами. При появлении rate limit, CAPTCHA, непроверенного состояния или требования входа выполнение прекращается.

## Структура

| Файл | Назначение |
| --- | --- |
| `vk_unified.py` | Главная CLI v6.24: VK API, общая очередь, отчёты, однопрофильные действия, выбор номера профиля для login/check |
| `vk_api_read.py` | Чтение публичных стен через `wall.get`, постраничная выборка, даты, контроль частоты и прогресса API |
| `vk_groups.py` | Конфигурация и очередь 57 сообществ, аудит и отчётность |
| `vk_batch.py` | Низкоуровневая проверка и обработка конкретного поста, SQLite, защита от дублей |
| `vk_test.py` | Playwright POC, проверки кнопок и диалога репоста |
| `vk_accounts.py` | Раздельные Chromium-профили и закрепление VK ID аккаунтов |
| `vk_account_smoke.py` | Однопостовый тест №2; отдельная SQLite, проверка личности и точного API-ID |
| `vk_groups.json` | Исходный список 57 публичных групп и настройки |
| `tests/` | Офлайн unit/regression tests; исторические тесты сохранены |
| `docs/DEVELOPMENT_CONTEXT.md` | **Полный контекст для следующего чата/Codex** |
| `docs/ARCHITECTURE.md` | Потоки данных, границы состояния и требования |
| `docs/ROADMAP.md` | Дальнейшие задачи с критериями приёмки |
| `.gitignore` | Исключение секретов, локальных профилей и баз |

## Защита данных

В публичный GitHub **не загружать**:

- `.vk-local-profile*`, cookies, localStorage, файлы браузерных сессий;
- `vk_batch.sqlite3`, `vk_batch_account_2.sqlite3`, `*.sqlite3*`, `vk_account_bindings.json` (локальные идентификаторы), `.vk-*.lock`;
- `VK_API_TOKEN`, `.env`, любые защищённые и сервисные ключи;
- реальные CSV-отчёты, авторизованный HTML/DOM VK, скриншоты с приватными данными;
- дампы HTTP, полный текст авторизованных страниц, логи с токенами.

См. `docs/ARCHITECTURE.md`, а также `docs/DEVELOPMENT_CONTEXT.md` для истории изменений и технических ограничений.


Для полного офлайн-регрессионного набора:

```cmd
py -m unittest discover -s tests -p "test_*.py" -q
```

**Статус тестов:** 15 новых unit-тестов двух профилей и 77 выборочных тестов v6.24 проходили локально в ходе разработки. Полный исторический набор на v6.24 не завершился в отведённое время из-за длительных ожиданий в старых браузерных тестах. Реальный вход во второй профиль и повторная проверка сессии подтверждены пользователем. CI и полный регресс необходимо привести к детерминированному выполнению.
